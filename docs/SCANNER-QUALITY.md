### Exact inverse phase: two real frames, not a pattern exemption

Engine **`0ce8fedc77873de71f75bbbe4626102c3856f86cfc4d759e9c375f52d152b672`** distinguishes an equal-area two-colour checkerboard in one frame from an exact temporal colour swap. The optional `pattern.inversePhase` witness requires the **same two opaque colours to exchange at every pixel** of the complete component between two consecutive analysed source frames. It records both actual relative timestamps, the compared pixel count and equal counts for each colour. The current timestamp must equal the retained spatial witness's `sampledAtMs`; all fields belong to that pair. A stronger later spatial witness carries its own pair, rather than combining evidence from different frames.

The previous-frame clock is cleared across malformed/out-of-order frames, excessive gaps, explicit interruption, geometry/source-geometry changes and temporal-epoch rollover. Identical accepted intervening frames advance the clock, so a previous pixel buffer is not mislabelled with an older frame's time. Unaligned input without retained prior pixels yields no inverse witness. Tests reject a single contradictory pixel, nonopaque input, both colours merely becoming brighter, unchanged phase, invalid chronology and incompatible geometry. Core validation rejects inconsistent pair times/counts; diagnostic sharing copies only the allowed fields.

The [26 targeted engine/core tests](../packages/analysis-engine/test/), including [schema and rendering checks](../packages/core/test/diagnostics.test.ts), and both package typechecks pass. An independent source review found no additional blocker. The renderer explicitly separates one-frame spatial balance from a demonstrated two-frame swap. **Neither establishes balance over the entire flash period, causal attribution or a normative fine-pattern exemption; candidates remain present.** No native performance or full-suite acceptance is inferred from these targeted checks.

The [current three-engine proof](../packages/analysis-engine/validation/wasm-inverse-phase-0.4.0-production-proof.json) retains **144 cases**, **23,058 frozen/current and 23,058 current JS/AUTO state checks**, **1,626 callbacks**, **10,159 kernel calls**, **522 mixed-history calls** and **4,698 independently checked masks**. It preserves the same six justified spatial-maximum changes relative to the old oracle. The [original temporal](../packages/analysis-engine/validation/detection-inverse-phase-0.4.0.json), [expanded temporal](../packages/analysis-engine/validation/expanded-inverse-phase-0.4.0.json) and [spatial/media](../packages/analysis-engine/validation/spatial-media-inverse-phase-0.4.0.json) gates all return `NO_NEW_MISMATCHES`: respectively 11/0/2/29, 129/0/18/251 with two invalid sources still unscored, and the unchanged 24-mask/36-video matrices with all **1,204 decoded frames/PTS** checked. ### Bundled exact WASM dense processing

Its 25th state pointer supplies the shared-history representative map: the kernel processes each independent representative once and skips aliases, while JS retains sparse/shared-history handling. The representative array is migrated into the same fixed memory, not duplicated. This removes the earlier all-independent restriction without sampling pixels or changing Float64 operation order, thresholds or diagnostic logic. ## Earlier 0.2 detection and measurement

- Engine `0.2.0-candidate` removes a starting-phase blind spot in the rolling flash window. Adversarial numeric sequences cover general and red candidates, discontinuities and irregular transitions. No flashing fixture is rendered on screen.
- Source viewport changes reset temporal history even if both source sizes map to the same analysis dimensions. Candidates on either side of a reset are not merged into a single continuous event.
- A capture window now records elapsed time, delay before the first submitted decoded frame and silence after the last one. A brief 60 fps burst cannot stand in for a whole 15-second observation. No timer-generated or repeated frames are counted as source evidence.
- Static sources may legitimately stop delivering updates. The scanner therefore reports unconfirmed continuity rather than asserting that silence proves a frozen source. Frame cadence and arrival-clock coverage remain separate measurements.
- Ended readers, worker failures and stale capture callbacks are handled explicitly. A failed frame transfer cannot leave the capture permanently busy; a callback from a cancelled session cannot alter the next session.
- Candidate times are explicitly relative to the first analysed frame. Leading capture delay is shown separately in local, hosted and exported reports.

## Autonomous discovery

Open shadow roots are traversed with bounded work: at most 12,000 elements and 64 roots per inventory. ARIA targets resolve within their component, so duplicate IDs in unrelated components cannot supply false evidence. Nested menu → tab → muted video → SPA navigation has a real browser regression fixture.

Composed ancestor checks preserve form, sensitive-panel, hidden and inert exclusions across component boundaries. Controls and links receive hit tests after scrolling and focusing, preventing synthetic clicks through overlays. An expanded but hidden, transparent or offscreen panel does not count as achieved. Incomplete tree traversal prevents active controls and link navigation; the report records the limit.

Closed shadow roots, iframe DOM, arbitrary custom controls and unsupported consent flows remain outside the action adapter. Their visible pixels may still appear in the captured viewport; that does not prove their interactive states were explored.

## Historical engine/runner 0.3: inspectable diagnostic evidence

The 0.3 implementation added the first detecting window of a representative analysis pixel: timestamped 8-bit sRGB samples, analysis/source geometry and a completeness flag. A volatile ring is limited to 16 MiB including timestamps and at most 96 frames (72 frames at 320 × 180; 18 at 640 × 360). It is cleared at resets and released on finish; no screenshots are persisted. Missing preceding context, truncation and non-opaque samples are explicit. Merged findings keep the first window rather than silently replacing it with later evidence. `qualifyingTransitions` records the seven-transition trigger; the compatible numeric `flashesInWindow` is 3.5, not four completed flash pairs or an exact event maximum.

Local, shared and standalone HTML reports show static luminance/red-ratio plots, a schematic candidate region, the measurement pixel and raw RGB samples. Lines connect samples without claiming intermediate measurements. The bounding rectangle is not an exact pixel mask or WCAG visual field. Imported evidence is rejected when its chronology, geometry, completeness or spatial counts contradict one another. Old reports without diagnostics remain readable.

The runner captures ephemeral document/URL and viewport context before an observation. Afterwards it inspects at most eight finding regions within a five-second budget, nine hit-test points and six element hints per region. Navigation, interrupted observations and context mismatches do not produce a mapping. Each mapping uses the finding's own dimensions; the DOM adapter also checks aspect ratio, DPR, scroll and visual zoom. Positional child paths are resolved through direct children and open shadow roots, with a round-trip identity check; they are not CSS selectors for `querySelector`. No page text, IDs, classes, URLs or custom tag names are retained. The raw URL/document token are used only transiently.

Hints show media kind and current animation counts, the inspection timestamp and delay after the observation. They remain **post-observation spatial hints, not a verified flash source**: DOM content can change without changing the viewport, sparse hit tests omit sources, pointer-events/pseudo-elements and closed roots/iframe contents are not resolved. These details are omitted from public snapshots by default and removed entirely from pseudonymized exports.

The implementation-independent **internal** numeric reference covers 1,630 cases with complete agreement, including phase/frequency, time-window boundaries, luminance/red thresholds and reset boundaries. It is distinct from the external TRACE set above and supplies no independent accuracy claim. The 0.3 trace-enabled CPU benchmark on Node 24.19.0/macOS arm64 measured median per-frame times over five trials: gradient/static/pulse 0.831/0.163/0.581 ms at 320 × 180 and 3.062/0.657/1.775 ms at 640 × 360. Capture, canvas readback and worker transfer are excluded; these are not observed browser frame rates.
