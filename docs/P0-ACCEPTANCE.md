## Implementation choices

The durable approved-upload queue lives in the website origin's IndexedDB after the user reviews and approves a snapshot. Original audits remain in extension IndexedDB. This differs from the initial extension-origin queue sketch: the website already owns the authenticated account and Turnstile flow, while frozen hashes, account binding, idempotency, cancellation and restart persistence remain enforced. It also allows report import without the extension.

Local site/route summaries are derived from versioned persisted scan jobs rather than duplicating all entities into separate local stores. Candidate grouping is conservative and separate from occurrences; it does not establish DOM defect identity. The later 0.4 scanner adds explicit local confirmation/resolution/reopening and compatible targeted rechecks; these are recorded review decisions, not automatic proof that a defect was fixed. Migration and deletion tests cover this storage choice.

Public-origin filtering is a conservative literal/hostname policy. It does not query DNS or identify arbitrary split-horizon domains under a public suffix; the uploader must still review the site and selected data. Legacy PUBLIC records are withheld from public reads, search and aggregates until their owner reconfirms the origin against the current policy. Private and unlisted access remain available under their normal controls.

## External gates — explicitly deferred

- Provision staging/production Cloudflare Workers, D1, HTTPS origins and runtime secrets.
- Real Turnstile, email verification/recovery and account/publication/withdrawal acceptance on staging and production.
- Configure actual GitHub deployment/feed/release environments, tag rules and merge-queue/review permissions.
- Set up private encrypted backup scheduling, independent durable erasure ledger, provider logs/retention, billing alerts and an actual hosted recovery drill.
- Measure provider Worker CPU, D1 billed rows/storage, mail/R2 usage and the complete monthly budget.
- Bootstrap production signing trust and R2/CDN distribution; verify cache hits and warm/cold delivery while the app/API/D1 are unavailable.
- Complete the supported native browser/OS capture matrix, including broader SPA/media implementations, minimise/sleep and background cases; one synthetic native SPA/media fixture is recorded, and unsupported contexts remain explicit.
- Build/review the official configured extension, then submit and verify Chrome Web Store distribution.

The later 0.4 implementation and its evidence boundaries are tracked in [SCANNER-QUALITY](SCANNER-QUALITY.md): during-event source clues and bounded regression reviews are implemented, while normative validation, proven causal DOM attribution and advanced analytics remain separate roadmap work. P2 local rule activation, durable updater and offline blocking are not included in P0. An empty signed feed provides no blocking coverage.
