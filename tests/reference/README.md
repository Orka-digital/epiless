# External numeric detection reference

Run from the repository root:

```sh
node --import tsx scripts/validate-detection.mjs
node --import tsx --test tests/reference/validate-detection.test.mjs
```

The first command prints deterministic JSON: candidate agreement, true/false positives and true/false negatives, separately for general and red flashing. It exits zero after a valid comparison even when discrepancies are found. `--require-match` additionally exits 2 for any discrepancy; malformed files or failed provenance checks exit 1. A successful run is not a WCAG verdict.

CI uses `pnpm validate:detection --check-baseline`. This mode compares each case with the reviewed `trace-pse/comparison-0.3.0.json` snapshot and exits 2 for any **new** mismatch. The two recorded disagreements remain visible and allowed; resolving either is accepted. Improving one case cannot conceal a regression in another, even when the total mismatch count stays the same. Corpus manifest hash, case IDs, types and external expected labels must match; changes require an explicit review of the baseline, not automatic regeneration. Engine source hashes may differ so this gate can assess subsequent implementations. This policy preserves the upstream labels and never turns known disagreements into expected successes.

The [0.3.0 comparison snapshot](trace-pse/comparison-0.3.0.json) records 11 found positive cases, zero missed positives, two unexpected candidates and 29 correctly negative cases. Its exact engine source and reference manifest hashes identify the measured version. The two unresolved staircase-luminance disagreements remain included in all metrics; see [Scanner quality](../../docs/SCANNER-QUALITY.md#engine-03-external-numeric-comparison).

The 42 cases are a fixed subset of the independently authored [TRACE RERC PSE test-media repository](https://github.com/traceRERC/pse-test-media), pinned at commit `ef78542aad496827f25064f57aaf13d6a741ba75`. Their source is described in [Jordan's 2025 benchmark paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC12249941/). All 45 upstream files, including the original license and interpretation notes, are stored unchanged. The manifest verifies their Git blob SHA-1 and SHA-256 before analysis. Source copyright, BSD-3-Clause conditions and disclaimer are retained in [LICENSE](trace-pse/upstream/LICENSE); TRACE does not endorse this product.

The subset was selected by documented pattern families before running this engine: fast transitions, spread flashes, approximate square waves, luminance staircases, reversed starting polarity, red saturation and chromaticity boundaries, and multicolour red transitions. Expected results come from upstream filename prefixes and their README explanations, not from our own algorithm. Positive `f`/`fr` patterns exceed the temporal and intensity thresholds; `c`, `l`, `y`, `s` and `d` variants test the respective below-threshold controls. The validator rejects relabelled expectations. The first comparison found eight missed positive cases and zero unexpected positives; those disagreements are useful detection evidence, not a reason to remove cases or change their labels.

Each unchanged 8-bit sRGBA row becomes one pixel at the documented 30 fps timestamp. No image or video is generated, displayed or played. No padding, scaling, colour conversion or repeated artificial source frames are added. Only the pattern's intended general or red candidate channel is scored; other channels are recorded separately.

This projection evaluates temporal/intensity behaviour only. It deliberately omits spatial masks and does not score the combined WCAG visual-field area condition, fine-pattern exception, motion compensation, capture/downsampling, HDR, display conditions or DOM attribution. Labels for the separate upstream `trace24` video sets concern proposed recommendations and must not be presented as WCAG conformance results. All-selected-case agreement is evidence on this fixed numeric subset, not independent certification, real-world sensitivity or medical safety. After this comparison has informed changes, the subset is a development regression set; new held-out cases are still required before estimating generalisation.

Useful subsequent validation keeps three layers separate: held-out external numeric patterns and area masks; lossless decoded file comparison with a documented independent tool/profile; and end-to-end browser capture with recorded dropped frames, resolution and colour-space conditions. [PEAT](https://mida.umd.edu/peat/) is a legacy Windows tool with use restrictions and an older proprietary engine. [Ofcom's broadcast guidance](https://www.ofcom.org.uk/siteassets/resources/documents/tv-radio-and-on-demand/broadcast-guidance/programme-guidance/broadcast-code-guidance/section-2-guidance-notes.pdf) uses a screen-area condition; [WCAG 2.2](https://www.w3.org/TR/WCAG22/#dfn-general-flash-and-red-flash-thresholds) instead specifies combined simultaneous area within a 10-degree visual field. Harding/Ofcom broadcast profiles are therefore not interchangeable with WCAG 2.2. Tool disagreement needs investigation, not a majority vote.
