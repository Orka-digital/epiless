# Numeric detector reference

`pnpm --filter @epi-less/analysis-engine reference` emits machine-readable
confusion matrices and fails when the streaming detector disagrees with this
internal reference. No video, animation or flashing image is rendered.

The 1,630 deterministic cases cover frequency and phase, seven versus six
qualifying transitions, half-open one-second windows, all 256 grayscale values
at the luminance and darker-state boundaries, saturation and chromaticity
sweeps, a fixed-seed irregular-cadence corpus, opposing red excursions and
capture discontinuities. Separate unit tests cover gradual excursions, spatial
separation, floating-point timestamps and the diagnostic retention limit.

`reference.ts` independently converts raw sRGB bytes through scalar arithmetic
and a matrix to luminance/CIE coordinates. It constructs a complete batch edge
list and exhaustively enumerates three disjoint opposing pairs followed by an
opposing continuation. It imports no detector code, lookup table, streaming
transition ring or pairing dynamic program. Its step-sequence scope does not
establish the correct interpretation of arbitrary multistep colour trajectories.
`run.ts` is the comparison adapter and is the only part that imports the engine.

The criteria come from the [W3C WCAG 2.2 definitions](https://www.w3.org/TR/WCAG22/#dfn-general-flash-and-red-flash-thresholds).
The conservative seven-transition candidate policy is also exercised against
separately maintained, verbatim external Trace Center fixtures under
`tests/reference/trace-pse`. Those external labels are not generated by this
reference, and their disagreements must remain visible. In particular, the
external multistep negative cases `l031_srgba.csv` and `y031_srgba.csv` produce
candidates in the detector's gradual peak/valley model. Internal agreement does
not resolve that interpretation difference or imply external agreement.

Neither this corpus nor a match establishes WCAG conformance, visual-field area,
real-world sensitivity, fine-pattern exceptions, colour management, medical
safety or state-of-the-art accuracy. These are numeric regression checks for
one analysis pixel in SDR sRGB; source dimensions, frame capture and spatial
behaviour need their separate checks.

## Rejected dense-loop follow-up experiments

[`dense-loop-0.4.0-rejected.json`](dense-loop-0.4.0-rejected.json) retains three
alternating trials per comparison, complete per-frame timings and exact source
hashes for two isolated proposals against production `342483aa…`: local array
references with inline general-transition logic, and a saturation-only 256 × 256
Int16 threshold table. Neither was integrated. The inline variant improved
translated texture but had no robust benefit on the native fixture's contrast-
limited RGB pattern; the table was slower and required another 131,072 bytes.

Both variants passed 126 complete report/live-callback comparisons, covering
1,554 findings and callbacks. For the table, reports differ by exactly the
explicitly asserted 131,072-byte state increase; original full report hashes
remain present. Its complete 16,777,216-colour proof has zero differences from
the original Float64 division, including the black exclusion. A stale inherited
benchmark scope sentence about unchanged allocation is identified in the JSON's
`metadataErratum`; actual measured budgets are 190,023,436 and 190,154,508 bytes.

The [compressed reconstruction archive](dense-loop-0.4.0-rejected-reconstruction.json.gz)
contains all three original source trees, patches, manifests, full proof records
and benchmark scripts. Its SHA-256 is recorded in the verification JSON. Extract
the `sources` entries into `<variant>/src`, the manifests at the extraction root
and the `harness` entries into `bench`; create the relative source links listed
under `setup.benchSourceLinks`. The scripts use Node 24.19.0 with the workspace's
`tsx`, refuse to overwrite evidence and must run sequentially on idle hardware.

These are numeric 1920 × 1080 `pushFrame` measurements with 90 frames, 15 excluded
warmup frames and diagnostics enabled. The added `low-contrast-rgb` workload uses
the exact native fixture shader's uint32 hash and RGB formula, with row origin
converted to top-left RGBA. It is a kernel reproduction, **not actual I420
capture, colour conversion, browser scheduling or native cadence evidence**.

## Rejected raw-frame buffer reuse

[`raw-reuse-0.4.0-rejected.json`](raw-reuse-0.4.0-rejected.json) preserves all
36 trials across six workloads, source hashes, per-frame timings, complete
lifetime and engine differential records. That experiment left production at `342483aa…`; the
isolated candidate was `47074e10…`. Three alternating trials found slower
entropy processing in every pair: median mean time **40.87 → 44.63 ms** and
median p95 **45.13 → 53.14 ms**. Texture improved **21.75 → 20.62 ms**, gradient
**9.70 → 9.28 ms**, and the contrast-limited RGB kernel **16.34 → 16.16 ms**;
pulse and sparse cases were practically unchanged. These mixed results failed
the no-regression gate, so the proposal was not integrated.

The candidate reused only a raw buffer fully removed during the current push.
A buffer promoted into the next delta's basis remained owned by that record.
There was no persistent pool or additional reserved memory. Lifetime checks
compared every retained payload, timestamp, trace and byte count, including
input non-aliasing, the 96-frame limit and 16 MiB byte pressure. In a 12-frame
1080p raw sequence, cumulative raw-buffer allocations fell from 12 to 2; this
does not mean a lower retained-memory budget or demonstrated browser speed.
The 1536 × 1536 epoch-reset test exercised the history class alone, beyond the
product's pixel cap. All 126 engine cases, 1,554 findings and 1,554 callbacks
remained identical, including 8,593 actual packed-path frames.

The [reconstruction archive](raw-reuse-0.4.0-rejected-reconstruction.json.gz)
preserves both source trees, the patch, manifests, harnesses and all original
outputs as UTF-8 strings. Its SHA-256 and every original file hash are in the
JSON. Extract source/scripts into a fresh directory under repository
`artifacts`, retaining old outputs separately; the archive's `setup` describes
the relative source links and Node 24 commands. Harnesses refuse to overwrite
evidence. The numeric low-contrast kernel uses the native shader's exact RGB
formula, but excludes capture, I420 conversion and scheduling. No native
throughput result follows from this rejected experiment.

## Bundled WASM dense kernel

Current engine source `c216fbe2c9de76354061c35ba4df09e7e0a25731e5be247f3a7092aca2ca687a`
retains the same packaged kernel as the preceding `f6611f36…` source: it integrates a **2,239-byte ABI 2** exact Float64 kernel. Its C source, generated TS byte
array and compiler manifest are retained under `src`. Temporal arrays are
shared with JS; a 25th pointer supplies the representative map, so aliases are
skipped and independent representatives can run beside shared histories. The
map is migrated, not duplicated. There is no per-frame state serialization,
pixel sampling or threshold change. Fixed memory cannot grow and detach the converter's input.
Initialization failure before measurement selects JS. A partial trap interrupts
the observation, resets state and rejects further frames without retrying the
same frame through another backend.

The historical **ABI 1** [prototype record](wasm-dense-0.4.0-prototype.json) retains **36 runs**:
six 1920 × 1080 workloads, the frozen `342483aa…` JS baseline and measured
`9b8b0d34…` prototype, with three trials per pair. Each trial has 90 numeric
frames, 15 excluded warmup frames and diagnostics enabled. Times include the
prototype's input copy and JS sharing/clustering/diagnostics. They exclude
capture, browser colour conversion and scheduling. These are measurements on
the available Mac, not native throughput of the integrated source.

| Contrast-limited RGB |       18.94 ms |                   10.29 ms |      11.41–11.61 ms |              14.11 ms |
| Entropy              |       42.34 ms |                   31.76 ms |      33.67–36.41 ms |              67.07 ms |
| Translated texture   |       23.76 ms |                   13.94 ms |      16.62–18.13 ms |              46.22 ms |
| Gradient             |       10.54 ms |                   10.25 ms |      13.56–16.26 ms |              29.24 ms |
| Pulse                |        8.55 ms |                    8.37 ms |      18.57–20.43 ms |              26.30 ms |
| Sparse detail        |        6.10 ms |                    6.00 ms |      14.53–14.82 ms |              26.86 ms |

All 75 timed contrast-limited frames in each WASM trial stay below 16.7 ms;
all 75 entropy frames in each trial remain above it. Texture retains spikes.
The timed gradient/pulse/sparse frames do not invoke the dense kernel, so their
small changes are not evidence of kernel acceleration. The prototype reserves
198,443,788 bytes versus the baseline's 190,023,436; the earlier ABI 1 integration additionally
accounts for the embedded 2,210-byte array. This is retained logical engine
state, not compiled-code, whole-process, GPU or transient GC peak memory.

The earlier **ABI 1** [production proof](wasm-dense-0.4.0-production-proof.json) reruns **126 cases**

values and callbacks match exactly; NaNs match semantically. Complete reports

behaviour preservation, not independent normative accuracy.

Unlike the pre-fix comparison, frozen accumulated spatial fields may intentionally
change, but only with independent proof. Before frozen `cluster()` consumes each
active mask, [the separate validator](../bench/spatial-witness.mjs) calculates
connected components and brute-force field sums. It examines **4,698 masks** and
allows exactly **six** stronger single-frame replacements in this corpus:
**68 pixels at 916.67 ms → 71 pixels at 1000 ms**, for the six 64 × 49
mixed-sharing variants. Each update retains full mask bytes, the source-frame
hash, strict ranking, timestamp, component count, pattern and motion from that
same frame. Frozen pattern/motion logic remains the reference for those fields.
No field is blindly discarded from comparison; every other report field stays
exact. Equal ranks keep the first witness. Three validator tests reject forged
time/count/pattern/motion/non-spatial evidence and non-increasing replacements.
The historical proofs and frozen source are unchanged.

This intentionally changes report retention, not pixel thresholds or temporal
histories. A separate small regression proves the real missed case: disconnected
components initially below the area cutoff later qualify together at **4/12**,
and their strongest actual frame is retained without rewriting the first live
source event or diagnostic trace. The related timeline fixes reject nodes seen
only in the ±150 ms context margin and mark transient viewport revision changes
incomplete. See [scanner quality](../../../docs/SCANNER-QUALITY.md#spatial-and-source-correctness-follow-up).

Recheck the committed kernel without installing a compiler:

```sh
pnpm --filter @epi-less/analysis-engine verify:kernel
```

Ordinary extension builds run the same source/byte-hash, fixed-flags,
imports/exports and ABI check before computing their source fingerprint or
replacing `dist`. The binary imports only its local memory. Source, manifest,
embedded bytes and verifier participate in the scanner fingerprint. This
catches stale files; it does not prove compilation from C.

The following local command uses the exact installed clang and wasm-ld 23.1.4,
compiles to a temporary directory and compares every byte without replacing
source or evidence. These paths are the Homebrew installation used for the
recorded successful **2,239-byte ABI 2** comparison; other installations can supply their
own executable paths for the same version.

```sh
EPILESS_WASM_CLANG=/opt/homebrew/opt/llvm/bin/clang \
EPILESS_WASM_LINKER=/opt/homebrew/opt/lld/bin/wasm-ld \
pnpm --filter @epi-less/analysis-engine verify:kernel:rebuild
```

No compiler is downloaded automatically. Hosted CI runs the lightweight build
check and numeric differential, **not the pinned compiler rebuild**. The
[manifest](../src/wasm/kernel-manifest.json) records the exact flags, including
disabled fast-math and floating-point contraction. Local byte reproducibility
does not establish another platform/toolchain's output or native performance.
