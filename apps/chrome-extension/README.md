# epi-less Chrome extension

Engine 0.4.0-candidate / runner 0.4.0 development preview for Chrome 116+. One Manifest V3 extension provides the toolbar, persistent local dashboard and DevTools panel. The autonomous runner navigates the **current tab**; it opens a quiet dashboard after capture starts. Captured frames and audio are not recorded to disk or uploaded; bounded numeric pixel samples may be retained as optional diagnostic evidence.

## Build and load

From the repository root:

```sh
pnpm --filter @epi-less/chrome-extension build
```

Open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select `apps/chrome-extension/dist`. Visit a normal HTTP(S) site, open the epi-less toolbar and choose **Scan deze website**. The extension asks for access to that origin. Closing the popup does not close the runner.

The default publication origin is `http://localhost:4321`. To build for the official installation, supply its exact HTTPS origin:

```sh
EPI_LESS_WEB_URL=https://your-official-host.example pnpm --filter @epi-less/chrome-extension build
```

The build generates the external-message allowlist. Runtime checks additionally require the exact origin, `/publish` path, newly opened tab ID, a random one-use nonce and a five-minute deadline. Choosing an upload preview only transfers the selected report into that preview. Authentication, Turnstile and explicit publication confirmation happen on the website.

The dense-pixel WASM kernel is bundled locally; ordinary builds need no C compiler or runtime download. Before replacing `dist`, the build checks that the committed C source, generated bytes, fixed flags and ABI agree. Its extension CSP permits the packaged WASM through `wasm-unsafe-eval`; it does not enable JavaScript `unsafe-eval`. Maintainers can run the separate [exact clang/wasm-ld 23.1.4 rebuild](../../packages/analysis-engine/validation/README.md#bundled-wasm-dense-kernel). Hosted CI performs the lightweight consistency check, not that compiler rebuild.

### Optional advanced interactions

The default build has no debugger permission. For genuine browser hover, build and load the separate advanced extension:

```sh
EPI_LESS_ADVANCED_INTERACTIONS=1 pnpm --filter @epi-less/chrome-extension build
```

Load `apps/chrome-extension/dist-advanced` and explicitly enable advanced hover interactions. Choose **Aparte scantab openen**, then open the epi-less toolbar on that new tab and choose **Start scan**. The second real toolbar gesture authorizes capture on that tab; preparation never starts capture. The original page stays in place. The advanced scan navigates its own temporary tab, keeps it while paused, and closes it after stopping or finishing. Reports remain local; original-node inspection is unavailable after that temporary document closes. This build declares Chrome's debugger permission and shows its debugger banner; keep DevTools closed on the scan tab. The pointer adapter uses actual browser input, not synthetic `mouseover` events. The normal scanner does not need this permission. Responsive scanning now uses a physical background window in both builds. Earlier CDP compact captures had black corner pixels despite matching dimensions and cadence; that mapping is not accepted, and old CDP replay recipes are refused. See [capture validation](../../docs/CAPTURE_VALIDATION.md) for the retained failures and the current acceptance boundary.

## Runtime boundaries

- A service worker owns the durable job lease, route queue and inspection actions. IndexedDB checkpoints survive popup closure and extension worker restarts.
- Chrome `tabCapture` creates a stream from the toolbar gesture. An offscreen document consumes it across navigations. `MediaStreamTrackProcessor` supplies actual `VideoFrame` timestamps without depending on the offscreen document compositor; `requestVideoFrameCallback` is the fallback.
- A bundled worker analyses frames serially, with at most three genuine source frames in flight to absorb brief processing spikes. FIFO order and source timestamps are retained; a full queue still records loss. It preserves native pixels within a 1920 × 1080 pixel budget and bounds retained analysis state to 256 MiB. Larger sources are rescaled. Dense processing uses an exact Float64 WASM kernel sharing its temporal arrays with JS. Initialization happens before observation and can fall back to JS; a partial runtime trap interrupts the observation and rejects subsequent frames. Native `VideoFrame.copyTo` writes directly into the stable analysis input. Reports retain actual backend-call and copied-byte counters alongside source/analysis dimensions, processing timings and skipped frames. Selecting WASM alone does not prove that a sparse observation invoked it.
- Retained engine `c216fbe2…` passes the 144-case three-engine spatial-witness comparison; the 11-scenario Chrome worker fixture verifies real WASM calls and direct input. Scanner `6770f520…` passes controlled native desktop/compact dense capture: 306/307 frames at 59.99685/59.79132 fps, 301/300 actual kernel calls, zero extra input-copy bytes and no interruption/rescaling. The separate encoded VP9 capture passes near 60 fps with exact sampled greys through shared JS processing. These observations still mark media replay unproven and the jobs remain partial. They are capture/detection evidence on one Mac, not native before/after video-fix proof. Current and historical failures remain in the [capture record](../../docs/CAPTURE_VALIDATION.md).
- Missing frames, background throttling, capture loss and worker restarts cannot produce a pass. A restarted worker marks its previous work interrupted; resumption starts a fresh capture segment through the toolbar.
- STOP/PAUSE dispatches the generation-scoped capture stop before waiting for page cancellation, which is bounded to one second. Stale requests cannot stop another job’s producer. Cleanup releases the owned capture/debugger/workspace resources; this does not prove exact layout restoration. The advanced native cancellation test still ends at 450 rather than 507 CSS pixels in height, and rejected workarounds are retained separately.
- Default budgets are 50 routes, depth 4 and 20 active minutes. The runner uses exact-origin URL policy, a strict control allowlist, bounded scrolling and muted supported media playback. Queries, transactions, form controls, cross-origin destinations and unsupported actions are excluded.
- Optional sitemap discovery checks `robots.txt`, permits at most three same-origin sitemap documents (256 KiB each) and 500 candidate URLs, and applies the same route policy and route budget. Requests omit credentials and refuse redirects. Sitemap candidates never count as measured coverage.
- Rendered same-origin links are activated through a conservative navigation adapter, preserving real-path client routing with `pushState`; ordinary navigation and safe same-origin redirects are also supported. The reached URL owns subsequent viewport segments. Redirect aliases remain in the visited set, and another alias reaching an already measured page contributes its transition without repeating the viewport. Rendered links retain their discovery page: after intervening routes, the runner returns there, restores the bounded discovery scroll position for lazy links, and tries supported consent/menu/disclosure/tab actions to reveal the link again. Source recovery allows at most six scroll/control steps. A missing source link becomes an explicit unobserved state, rather than an HTTP fallback being mistaken for the client route. Navigation restoration shares a 30-second deadline and the job budget. Hash-router targets are explicitly skipped because fragment identity is omitted for privacy; quick/extended mode can still observe their current viewport, with limited scope.
- Inventories refresh after every action or scroll, discovering newly revealed menu/tab/video controls and lazy-loaded links. Scrolling is limited to six steps and 50,000 pixels, within the per-route action and total time budgets. Supported carousels use explicit `aria-roledescription="carousel"`/`"slide"` and next/previous buttons. A control can reveal up to four distinct states; repeating a state stops that sequence. The shared 12-action route budget can leave further states unobserved.
- Within the shared action budget, the runner can prepare up to two existing, safely controlled, finite seekable loops near their end and observe a five-second interval. A tested seam requires both actual playback-clock and compositor-presentation wraps. It does not turn a non-looping video into a loop or claim whole-video coverage. Fullscreen, enlarged media and additional compact-loop states remain explicitly skipped or unreached when unsupported. One retained controlled native loop fixture retains 310 frames near 60 fps and two independently observed wraps; its artificial moving low-contrast four-pixel marker is part of that evidence boundary.
- The plan adds up to two focus observations, up to two genuine hover observations in the advanced build, and a seven-second delayed-state observation. The compact profile targets 600 CSS pixels wide with the original DPR and uses at most two of the shared 12 route actions: a five-second viewport observation and one supported responsive control. The old capture producer is released before moving the same tab into an owned, unfocused normal window behind the dashboard, then physically resizing it. The tab is active inside that unfocused window so Chrome actually lays it out. The original window must remain normal, focused and unchanged during this bounded step; pinned/grouped tabs and changed cover/focus are explicitly unreached or interrupted. Cleanup restores the workspace geometry before returning the tab to its original index. A session-scoped lease supports cleanup after a worker restart; user-moved tabs, user-added tabs and a closed original window are preserved. If Chrome stops between creating the window and persisting its ownership, the earlier move intent produces a local manual-restore notice; the scanner does not guess ownership or move an uncertain tab. Browser fixtures verify this lifecycle and actual focus events; native pixel acceptance remains separately documented. Budget exhaustion and unsupported controls never count as tested states.

## Local history and exports

The dashboard groups local audits by exact origin, with discovered/measured routes, attempted/completed audits, candidate groups, occurrences, capture-quality ratio and the latest job state. Grouping uses route, scenario, engine version, sample size, candidate type and exact sampled region; it is conservative local grouping, not verified DOM identity. A missing observation never marks an older candidate resolved.

Export one audit as JSON or a standalone, script-free, print-friendly HTML report. HTML includes static timelines, findings and candidate regions in analysis pixels, criteria, recommendations, coverage and capture limitations. Candidate regions are not CSS/DOM identity or a normative visual-field measurement; downsampling is explicit. Site history and the complete local index have versioned JSON exports. Optional pseudonymization replaces origins, paths and diagnostic text; timestamps and measurements remain, so it is not an anonymity guarantee. The option does not change the separate online upload preview.

### Diagnostic evidence and element inspection

Engine 0.4 retains bounded representative-pixel RGB traces and exact counts of simultaneously qualifying pixels, including disconnected regions. When later observations are stronger, their complete actual spatial frame is retained with its own time, components, motion and pattern; the original detecting event remains separate. Static reports show measurements without replaying media. Native worker observations use W3C's 341 × 256 CSS-pixel reference field at standard page and pinch zoom, mapped through verified native DPR (682 × 512 source pixels at DPR 2). Missing or inconsistent mapping, rescaling and any observed viewport/zoom change invalidate only the reference comparison; pixel candidates remain. Actual display geometry and viewing distance remain unknown; this is a reference comparison, not physical calibration or a WCAG verdict. Reference area, narrow motion and checkerboard evidence never automatically excludes a candidate.

During an observation, a bounded DOM sampler records geometry, scroll positions, mutation counts, allowlisted animation timing/property categories and video position at a target cadence of roughly 30 samples per second (rAF with a timer fallback; target and animation inventories are cached separately). It retains a three-second live ring and at most eight finding windows. Each window is matched against retained per-frame source timestamps and receipt epochs; DOM read intervals, boundary error and offset spread are recorded separately. Chrome capture timestamps are not assumed to share the document clock. Unknown compositor/source latency, missing samples, truncation and changed documents or viewports remain explicit. The DOM samples are not atomic with video frames and do not prove causality. A source candidate requires an actual read inside the detecting window. Reads in the ±150 ms margin remain contextual and cannot produce an in-window repair clue. Post-observation spatial hints remain a clearly labelled fallback.

Structural paths walk direct children and open shadow roots, not `querySelector`. No page text, IDs, classes, media URLs, animation names or raw keyframe values are retained. In the original tab's DevTools panel, **Inspecteer** opens the retained original node in Elements while its local reference is valid. Navigation, removal, expiry or replacing the node at the same path invalidates that reference. The dashboard cannot silently open DevTools. Inspection tokens are local only and are stripped from exported/shared reports.

### Review and targeted recheck

A local review can mark a candidate confirmed or a false positive with a note. A targeted recheck opens the saved route in a new tab and requires a new toolbar capture gesture, then replays its bounded scenario recipe. Comparison checks the exact cold-build source fingerprint, engine/runner version, route, replay state, viewport/DPR, analysed resolution and capture adequacy. It reports **reobserved**, **not observed** or **incomparable**. A completed route, different geometry or insufficient cadence cannot establish a fix.

Document/animation phase is also required. A newly loaded page measured too early can miss an unchanged delayed effect. The runner records bounded document and CSS/Web Animation clocks locally and can wait up to 30 seconds to align a supported replay, with at most a 500 ms endpoint extension. An animation starting near an action supplies additional timing context; it never waives the original document interval, because timing correlation does not prove that the action caused it. Missing clocks, unresolved pending animations, incomplete discovery or an unproven candidate-time boundary prevent a negative comparison. Removing the animation can still be a valid fix; matching keyframe contents is not required. The dashboard explains these limits and shows the measured document/video timing.

Historical records without phase evidence remain readable, and earlier reviews are preserved. They cannot support a new “resolved” transition under the current guard. The native `6770f520…` recheck described below retains its original comparator/build boundary; it is not new native acceptance of this phase guard. Current browser-clock fixtures exercise phase behavior with explicitly synthetic capture-quality/candidate records.

Seekable file-media recipes additionally preserve source-locator hashes, exact begin positions, rate and existing loop settings locally. The hash identifies an address, not the file bytes: replacing a video at the same address can be the fix. A comparable negative requires the original actually presented PTS sequence again, adequate playback progress and complete discovery. Missing compositor callbacks, frozen presentation, changed media, unseekable/live sources and timelines exceeding 24 hours remain unsupported. A bounded 500 ms extension can reach the original observed endpoint; it cannot substitute a different clip. Natural seeking-event order is matched to one unique timer/rVFC loop witness; a second seek cannot reuse it.

Real browser tests cover media replay and the actual runner/IndexedDB path with a synthetic offscreen boundary. A separate native toolbar-authorized proof on unchanged scanner `6770f520…` follows signal → fixed file → signal through the same source URL: 307/306/307 captured frames near 60 fps at 1800 × 1126, all 53 actual PTS from 0 to 2080 ms, and the complete 0–2120 ms clip interval. The production comparison returns `NOT_OBSERVED` then `REOBSERVED`; this is one controlled seekable-video case with the ordinary 20s marker. Independent file hashes prove the intentional fixture-content change; the scanner itself proves locator and observed-interval compatibility. See the [retained native verification](../../tests/extension/evidence/scanner-v04-native-media-recheck-verification.json). Earlier native encoded/dense fixtures still carry `MEDIA_REPLAY_NOT_REPRODUCIBLE` and remain separate evidence. Playback metadata stays local and is stripped from publication and pseudonymized exports.

Marking an issue resolved requires a prior confirmation and a compatible recheck in which it was not observed; reopening requires a later compatible observation. After a resolution or reopening, an older negative recheck cannot close the issue again, even if the user reconfirms it. These are explicit local reviews, not automatic proof that the same underlying DOM defect disappeared. Reviews and replay controls are not published. Pseudonymized exports also remove timelines and replay context.

The [numeric reference](../../tests/reference/README.md), [lossless spatial/media comparison](../../tests/reference/trace-spatial/README.md) and [scanner quality record](../../docs/SCANNER-QUALITY.md) record case-level agreements, disagreements and validation boundaries. Numeric arrays and decoded files are analysed without rendering flashing content. Normal sharing omits detailed diagnostics unless explicitly selected.

Compact audit history and candidate counts remain until deletion. Detailed events default to 90 days, with 30-day, 365-day and keep-until-deleted choices. Expiry preserves aggregate identities/counts and quality, drops individual event timings/messages and marks exported reports explicitly incomplete. Choosing a shorter period applies immediately; increasing it cannot restore deleted detail. The IndexedDB v1→v2 migration is additive and covered with the actual store module in Chromium. New audits preserve their engine version; legacy records lacking it are labelled `legacy-unrecorded`.

Delete one audit, one site's history or all local data from the dashboard. A running or paused scan must first be stopped. Local deletion also removes its unused extension transfer nonces; online publications are independently managed on the website.

## Known preview limits and release gates

This implementation is a runnable development baseline, **not a validated WCAG conformance tool or a released blocker**. Current native loop, dense-background and encoded-video fixtures pass their explicit capture criteria on this Mac; one controlled native video fix/recurrence chain also preserves the original presented clip. Whole jobs can retain untested or inadequate navigation states even when the measured observation is compatible. Source correlation does not establish causality. These observations do not validate every video, codec, page or machine.

The [capture record](../../docs/CAPTURE_VALIDATION.md) preserves original low-cadence runs, rejected CDP black-image mappings, unsuccessful layout-restoration experiments and each accepted build separately. A fixture PASS never replaces its report’s limitations.

The following remain release gates:

- General compact/responsive reliability and exact advanced cancellation layout restoration. The physical background workspace has accepted native pixel-mapping/cadence fixtures; the former CDP mapping remains disabled after persistent black pixels despite matching dimensions. The advanced CSS-height failure remains open even though its resources are released.

- Reliable temporal and spatial coverage across realistic workloads: frame skips, downsampling or inadequate continuity still produce `INCONCLUSIVE`, even when the average exceeds 50 fps. The separate 36-run WASM prototype improves the contrast-limited RGB workload from 18.94 to 10.29 ms per frame, but entropy still takes 31.76 ms on average and peaks at 67.07 ms. Those numeric CPU timings exclude native capture/conversion. Only this Mac has native evidence; general 60 fps is not established. Static pages can produce few frames; that is never treated as proof of safety.
- Other Chrome/OS versions, tab/window changes, minimization, sleep and SPA capture continuity need separate browser evidence. Chrome 116 is the API minimum, not a tested compatibility guarantee.
- Independent general/red-flash threshold adjudication, colour/HDR validation and physically justified visual-field attribution. The expanded temporal set has 398 scored cases (129 TP, 0 FN, 18 FP, 251 TN), with two malformed cases unscored. Exact mask and decoded-media comparisons retain source contradictions and all disagreements; these are regression evidence, not validated real-world accuracy.
- Initial navigation segments and bounded sitemap discovery are implemented, with explicit transition context and discovery limits. Native capture coverage across the full compatibility matrix remains a release gate. The runner supports rendered real-path SPA links, ARIA menu/disclosure/tab controls, explicit carousel adapters, progressing muted videos and two reject-only consent adapters. Custom components and other consent systems can remain unobserved.
- Cross-origin or policy-blocked redirects terminate/skip the observation. A safe same-origin redirect is recorded with its reached destination. Unexpected path/query/hash-router changes during an action interrupt the mixed-route observation; supported destinations are queued for a separate viewport measurement. This cannot undo a server redirect or side effect that has already happened in the scanned page. Only scan sites you intend to navigate in the current browser session.
- Resume begins the interrupted route again from a known page state and preserves earlier segments. It never replays an uncheckpointed arbitrary action.

The browser fixtures use static pages and numeric pixel sequences; the optional cadence fixture adds only a tiny, slowly moving, low-contrast marker. The separate media validator encodes and decodes real FFV1 files without playing them.

```sh
pnpm --filter @epi-less/chrome-extension test:browser
# Isolated headed browser; start the scan using its actual extension toolbar.
EPI_LESS_FIXTURE_MOTION=1 node tests/extension/native-fixture.mjs
# Non-flashing menu/tab/media, pushState, redirect, lazy content and consent adapters.
EPI_LESS_FIXTURE_INTERACTIVE=1 node tests/extension/native-fixture.mjs
```

The browser checks cover a real IndexedDB migration, persisted stop/restart, JSON and offline accessible HTML exports, site/all history export and deletion, retention preferences, single-use hosted transfer and form-associated or cancelled DOM actions. Unit checks cover extended-mode bounds, conservative deduplication, event expiry, export escaping/pseudonymization and bounded robots/sitemap discovery. The DOM suite additionally exercises nested menu/tab/media discovery, actual muted playback/restoration, carousel state changes, known/unknown consent boundaries, lazy growth, real pushState links and sanitized action transitions. Unit checks distinguish same-origin reached redirects, unsupported hash routes and bounded lazy scrolling. Native fixture environment exports include a SHA-256 fingerprint of the built extension. Cold builds additionally embed a deterministic source/toolchain fingerprint in each job and report; targeted rechecks and resume require an exact match. Unbundled/watch builds have no persistent identity and cannot establish compatibility. Additional fixtures cover temporal DOM sampling across mutation/scroll/media changes, original-node inspection through the real DevTools Elements selection, genuine browser hover, scenario replay and conservative recheck decisions. Native capture still needs the real toolbar gesture; an automated popup open is not equivalent authorisation.

The 11-scenario numeric Chrome worker fixture also passes on ABI 2 and proves actual dense WASM execution, direct `copyTo` without an extra input copy, accounted RGBA-transfer copies and complete finding/live-event/non-performance-quality agreement with a test-only forced-JS bundle. Its seven earlier conversion/reference cases remain. The current 144-case three-engine comparison includes 522 partially shared kernel calls and checks every temporal value and callback. It independently reconstructs 4,698 spatial masks and explains six stronger-frame report changes against the frozen reference; current JS and WASM reports agree completely apart from explicit backend/memory accounting. These checks render no buffers and do not replace extension-CSP or native capture validation.
